# Контекст выбранного target

Project Manifest выбирает repository/target/worktree и подключённые базы. Нативный harness обнаруживает ресурсы; этот манифест не создаёт собственный loader, registry или общий обязательный plugin.

До запуска выбери skills задачи из закреплённых баз. Подключай отдельные директории skill, сохраняя их относительные references/scripts; ссылка на весь каталог skills раскрывает лишние metadata. Не складывай stack-specific skills в корень многоприложенного repository: он наследуется дочерними targets. Sources манифестов остаются вне областей автообнаружения продукта.

Вход target — AGENTS.md с ID target, ссылкой на внешнюю адаптацию и выбранными нормами. CLAUDE.md ссылается на AGENTS.md. Для standalone skill, который ссылается на docs своей базы, проверь разрешение этих ссылок в выбранном harness; не устанавливай один SKILL.md отдельно от базы. При необходимости нативной физической копии генерируй её из закреплённого источника с проверенными зависимостями, не редактируй отдельно.

Четыре разных проверки:

1. Discovery: какие ресурсы найдены, откуда и в каком scope.
2. Metadata: какие имена/описания представлены модели или выборщику.
3. Body: какие инструкции действительно прочитаны для задачи.
4. Activation: какие tools/MCP/hooks/extensions активны независимо от skills.

Тест discovery не доказывает остальные три. Отключение автоподбора не всегда скрывает имя; скрытие skill не выключает plugin tool. Не обещай изоляцию только по layout или фразе «не читать».

Выбери один адаптер:

- [Codex CLI](harness/codex.md)
- [Claude Code CLI](harness/claude.md)
- [Pi](harness/pi.md)
- [OpenCode](harness/opencode.md)

Проверяй также ancestors, user/admin/system ресурсы и совпадение имён. Если невыбранный стек унаследован, настрой поддерживаемое локальное исключение до продуктовой работы; глобальные настройки без поручения не меняются. Не отключай обязательную managed policy. Если её требования не позволяют нужное разделение, обозначь ограничение вместо обещания строгой изоляции.

Для смены target/набора возможностей начинай новый сеанс. cd не удаляет уже загруженный текст. Scoping контекста не является sandbox и не ограничивает физический доступ к файлам.

## Проверка без модели

`npm run test:native` требует установленных Codex, Pi и OpenCode. Создаёт изолированный Git fixture с двумя target и symlink skills в e2e/tmp, вызывает Codex skills/list, OpenCode debug skill и Pi get_commands. Ни prompt, ни model turn не отправляется. Ничего не устанавливается в глобальные каталоги. Результаты сохраняются локально; точные версии выводятся на запуске.

Проверка устанавливает принадлежность skills соседним targets и явный Pi allowlist. Она не доказывает полный системный prompt, выполнение skills, фильтрацию tool permissions или отсутствие всех глобальных расширений. Для Claude CLI здесь нет автоматической проверки discovery; версия и документированный механизм отмечены в его адаптере.

Для Pi дополнительно доступна проверка подготовленного system prompt и tool allowlist через установленный нативный SDK, без модели. Команда, отрицательный контроль SYSTEM.md и границы доказательства описаны в [Pi](harness/pi.md). Она не подменяет проверку обычного CLI-сеанса.
